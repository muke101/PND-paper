\RevBLink{3} \textbf{Re-routing memory instructions \& hardware cost of PG-MDP} PG-MDP requires no redirection of u-ops in the LSU. Labelled loads simply carry an additional bit, available since decode, which can hardwire to MDP to always return no dependency on lookup. The additional decode overhead is likewise trivial for AArch64 and RISCV (X86 is discussed in response to reviewer C), as the opcode hint is in a fixed position in the ISA and requires no additional critical path logic beyond what is already required to decode regular load instructions. This brings the total hardware overhead for PG-MDP for these architectures to a handful of additional logic gates.

\RevB{4} \textbf{Applicability beyond Store Sets.} The majority of IPC gain that PG-MDP delivers in our results does indeed come from aliasing, as shown by the change in IPC gain as Store Set size is scaled in Fig. 1 and 6. However as PG-MDP is orthogonal to the underlying MDP it is not only applicable to Store Sets and has potential to deliver gains with any capacity-constrained predictor, which as established is unanimous in the class of processors we target.

More importantly, PG-MDP is orthogonal to the underlying MDP: it targets false-dependence predictions regardless of whether they arise from aliasing or the predictor mechanism itself.

\RevDLink{1} \textbf{Comparison to other approaches.} We have extended the evaluation to include comparison against more memory dependence prediction techniques. This includes the original Store Sets~\cite{storesets}, XS Store Sets filtered with a load-wait table~\cite{kessler1999alpha} (i.e. only loads that hit in the load-wait table index XS Store Sets), a reproduction of Feedback-Directed Memory Disambiguation Through Store Distance Analysis~\cite{storedistance}, and for completeness 'Always Speculate' and 'Never Speculate' runs. The evaluation shows that PG-MDP outperforms a load-wait table filter mechanism, even for a table with as much capacity as XS Store Sets itself. It further shows that \cite{storedistance} only delivers an additional 0.55\% IPC over PG-MDP despite incurring the cost of encoding an additional 5 bits in every load instruction (the fetch bandwidth performance penalty of which we have generously not modelled).
